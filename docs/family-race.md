# 가족 운빨 달리기 · v0.3

가족 5명이 각자 원하는 시간에 같은 주간 경기에서 달립니다. 다른 사람 차례를 기다리지 않습니다. 결승선은 없으며 일요일이 끝났을 때 가장 멀리 간 가족이 우승합니다.

## 규칙

- 매일 주사위 3회. 한국 시간 0시에 새로 3회를 받고, 남은 기회는 이월되지 않습니다.
- 주사위는 1~6이 같은 확률입니다. 서버에서 결과를 정합니다.
- 각 굴림의 이벤트는 일반 이동 80%, 숫자의 두 배 전진 10%, 주사위 숫자와 관계없이 뒤로 3칸 10%입니다.
- 출발선은 0칸이고, 뒤로 이동해도 0보다 작아지지 않습니다. 실제 이동 거리를 기록합니다.
- 한 경기는 월요일 0시부터 다음 월요일 0시 직전까지입니다. 한국 시간 기준입니다.
- 참여한 가족의 누적 거리로 순위를 정합니다. 1·2·3위 보상은 100·60·30P이고 이후 순위는 0P입니다.
- 동점은 공동 순위와 같은 보상을 받습니다. 공동 1위 두 명 다음은 3위입니다. 한 번도 굴리지 않은 가족은 순위·보상에서 제외됩니다. 굴렸지만 0칸인 가족은 참여자로 집계됩니다.
- 월요일에 위치는 0에서 새로 시작하고, 결산한 포인트는 계정별로 누적됩니다. 포인트는 게임 기록이며 구매·송금·교환 기능이 없습니다.

## 앱 동작

게임 탭을 열거나 앱으로 돌아오면 서버에서 최신 판을 가져옵니다. 자정에도 새 판을 다시 확인하며 수동 새로고침을 제공합니다. 현재 순위는 마지막 조회 기준이고, 다른 가족의 이동은 새로고침으로 확인합니다. 인터넷 연결 없이 주사위를 굴리지는 않습니다.

주사위를 누르기 전에 서버 주소와 가족 ID별 요청 UUID를 기기에 보관합니다. 응답이 끊겼거나 앱이 종료되어도 같은 UUID로 재시도하여 기존 결과를 돌려받습니다. 응답을 확인해야 요청 UUID를 지우고 다음 기회를 사용합니다. 이전 날짜·이전 경기의 요청이라면 해당 결과를 표시하고 현재 남은 기회는 그대로 보존합니다. 불확실한 요청이 남아 있으면 버튼에 **보내던 주사위 결과 확인**이 표시됩니다.

앱 데이터 삭제·재설치 후에는 기기의 대기 요청 UUID가 사라질 수 있습니다. 서버의 이미 사용한 기회와 기록은 유지되며 발자국에서 확인할 수 있습니다. 같은 APK 서명으로 업데이트하면 대기 요청도 유지됩니다.

## 서버 저장·결산

`race_rolls`는 요청 UUID, 가족, 경기 시작일, 플레이 날짜, 당일 차수, 주사위·이벤트·실제 이동·최종 위치를 보관합니다. `(member_id, play_day, turn)`과 요청 UUID에 유일 제약을 둡니다. 한 SQLite 연결의 트랜잭션에서 횟수 확인·추첨·저장을 직렬화합니다. 사용자 입력으로 결과·날짜·가족을 선택할 수 없습니다.

`race_rewards`는 경기·가족별 보상 한 건을 보관합니다. 완료 경기 결산과 조회·굴림이 같은 트랜잭션에서 수행되며 재조회로 보상이 늘어나지 않습니다. 종료 시점에 서버가 꺼져 있어도 다음 조회에서 누락된 경기를 정산합니다. 서버 시계는 정확히 맞춰 두어야 합니다.

## 인증 API

모든 경로는 기존 가족 Bearer 인증을 사용합니다. 응답은 `Cache-Control: no-store`입니다.

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/api/v1/games/race` | 현재 경기·서버 날짜·남은 기회·가족 위치·누적 포인트·최근 10회·지난주 결과 |
| POST | `/api/v1/games/race/rolls` | 주사위 1회. `Idempotency-Key: UUID` 필수, 요청 본문 없음 |

POST 응답은 `{ game, roll }`입니다. 같은 UUID를 다시 보내면 같은 `roll`과 현재 `game`을 반환합니다. 다른 가족의 UUID 재사용이나 당일 3회 소진은 409, 잘못된 UUID·헤더 누락은 400, 로그인 누락·만료는 401입니다. 서버 오류·타임아웃 뒤에는 새 UUID를 만들지 말고 기존 UUID로 재시도합니다.
